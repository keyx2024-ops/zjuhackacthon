# 需求分析

## 1. 问题陈述

将 7 本同一学科的教材整合压缩到不超过原始体量 **30%** 的精华版本，同时：
- **保证教学完整性**：核心知识点、定理、方法不丢失
- **去除冗余**：合并不同教材中描述同一概念的重复内容
- **结构化输出**：构建可视化知识图谱，支持精准问答和教师审阅

## 2. 子问题分解

### 2.1 知识点粒度定义

**问题**：什么是"一个知识点"？

**答案**：知识点是一个**独立、可解释的概念单元**，具有以下特征：
- 有明确的名称（如"光合作用"、"勾股定理"）
- 有完整的定义（一句到一段话）
- 有明确的类别（concept / theorem / method / example / application / definition）
- 在教材中有明确的出处（章节 + 页码）

**反例**：
- 太粗：整个章节作为一个"知识点"
- 太细：单个名词（如"细胞"作为知识点，但"细胞的结构"作为另一个）

### 2.2 重复判定标准

**问题**：什么时候认为两本教材的两个知识点是重复的？

**答案**：双重判定
1. **第一层**：Embedding 余弦相似度 ≥ 0.85
2. **第二层**：LLM 判定为 EQUIVALENT（核心概念实质相同）

**判定示例**：
- ✅ 等价：「白细胞」与「leukocyte」（仅语言不同）
- ✅ 等价：「细胞分裂」与「细胞繁殖」（同义不同名）
- ❌ 不等价：「细胞」与「细胞膜」（包含关系，不是同一概念）
- ❌ 不等价：「光合作用」与「呼吸作用」（相似但相反过程）

### 2.3 压缩比定义与控制

**问题**：什么是"压缩比"？

**定义**：
```
压缩比 = 整合后总字数 / 原始 7 本教材总字数 × 100%
目标：≤ 30%
```

**控制策略**（三阶段）：

1. **Stage 1**：合并等价知识点（自然压缩，保留高质量版本）
2. **Stage 2**：估算当前压缩比
3. **Stage 3**（如未达标）：删除低重要性节点
   - 优先删除：example / application 类
   - 保护节点：theorem / definition / 高频出现节点

### 2.4 教学完整性

**问题**：如何衡量"不打折的教学效果"？

**指标**：
1. **核心覆盖率**：所有 7 本教材都涉及的知识点 100% 保留
2. **关系保留率**：knowledge_relation 中的核心关系（prerequisite, contains）≥ 90%
3. **出处可追溯**：每个保留的知识点都能追溯到至少 1 本原教材

### 2.5 RAG 问答的"精准"标准

**问题**：什么是"精准"？

**标准**：
1. **基于原文**：回答的每个关键信息点必须基于检索到的上下文
2. **明确引用**：使用 `[N]` 标记，引用包括 [教材名, 章节, 页码]
3. **不编造**：上下文不足时明确说"无法回答"
4. **响应时间**：< 5 秒

## 3. 用户故事

### 3.1 教师 - 备课场景

```
作为一名生物老师，
我希望系统帮我整合 5 本不同版本的高中生物教材，
以便我快速找到核心知识点和不同教材的差异点，
节省备课时间。
```

### 3.2 教师 - 出题场景

```
作为一名教研员，
我希望基于整合后的知识库提问，
得到带引用的精准回答，
以便我能验证答案并出题。
```

### 3.3 教师 - 修订场景

```
作为一名学科专家，
我希望审阅系统的整合决策，
对不合理的合并/删除进行修改，
让最终的知识体系符合教学规律。
```

## 4. 功能边界

### 4.1 在范围内（必须实现）

- ✅ 多格式教材解析（PDF/DOCX/MD/TXT）
- ✅ 单本教材知识图谱构建与可视化
- ✅ 跨教材知识点对齐与整合
- ✅ 压缩比控制（≤30%）
- ✅ RAG 精准问答（带引用）
- ✅ 多轮对话修改决策
- ✅ Web 交互界面

### 4.2 在范围外（不实现）

- ❌ 自动出题、批改作业
- ❌ 学生学习进度追踪
- ❌ 跨学科知识融合（仅同学科）
- ❌ 教材推荐系统
- ❌ 大规模生产级部署（百万级知识点）

## 5. 非功能性需求

| 维度 | 要求 |
|-----|------|
| 性能 | RAG 问答 < 5s，整合 7 本教材 < 5min |
| 可用性 | 单页应用，所有功能在浏览器中可用 |
| 可部署性 | Docker Compose 一键部署 |
| 安全性 | API key 通过环境变量管理，不硬编码 |
| 可扩展性 | 支持后续接入更多文件格式、检索算法 |

## 6. 数据流

```
教材文件 (PDF/DOCX/MD/TXT)
    ↓ 文件解析
结构化教材 (Textbook + Chapters)
    ↓ 知识提取
知识点 + 关系 (KnowledgePoint + KnowledgeRelation)
    ↓ 图谱构建
知识图谱 (KnowledgeGraph)
    ↓ 跨教材对齐
等价知识点组 (EquivalentGroups)
    ↓ 整合决策
整合结果 (IntegrationResult)
    ↓ RAG 索引
向量索引 (FAISS) + 倒排索引 (BM25)
    ↓ 用户问题
检索 + 生成
带引用的回答 (RAGResponse)
```

## 7. 验收标准

- [ ] 上传 7 本教材，系统正确识别每本教材的章节结构
- [ ] 为每本教材生成知识图谱，前端可视化展示
- [ ] 跨教材整合后，压缩比 ≤ 30%
- [ ] 整合后保留所有 7 本教材都涉及的核心知识点
- [ ] RAG 问答回答中包含来源引用 [教材名, 章节, 页码]
- [ ] 教师对话修改一个整合决策，知识图谱实时更新
- [ ] 整个系统在浏览器中可正常运行（不需安装客户端）
